\section{Approach: Evidence-Checked Triage}
\label{sec:approach}

Figure~\ref{fig:pipeline} summarizes the pipeline, in which the shaded arms query the LLM and the remaining stages are deterministic. L sees only the alert and its enclosing function, whereas D, E and EC also read the EvidenceRecord, and EC reuses E's replies unchanged so that the two arms share every model response. All components after the baseline are our own design and implementation, comprising about 3{,}000 lines of Python, and the model is reached through the NUS SoCLaaS service without any existing neuro-symbolic analyzer, released tool or prebuilt workflow.

\subsection{Evidence extraction}
For each alert we parse the enclosing function and run an intraprocedural abstract interpretation over its statements.

\paragraph{Values.}
Abstract values are finite sets of concrete Python constants, including small lists, dicts and paths whose elements may themselves be abstract, together with three abstract elements ordered by severity. \textsc{trusted} marks an untainted configuration value such as a module constant, \textsc{unknown} marks an unmodelled value that might hide anything, and \textsc{tainted} marks a value that is attacker-controlled under the policy.

\paragraph{Statements.}
The analysis walks the statements of the function in source order. Expressions are constant-folded, and the supported string, path and container operations are interpreted element by element. For example, \texttt{lst.append(param); lst.pop(0); bar = lst[1]} evaluates to a constant when the selected element is one. An \texttt{and} or \texttt{or} yields its deciding operand, and operands that Python would skip are not evaluated. A condition with a known truth value prunes the infeasible branch of an \texttt{if}, a \texttt{match} or a conditional expression, and definitions made in a pruned branch are recorded as lying \emph{on an infeasible path}. Loops are iterated at most five times, and a loop that has not converged by then is widened and marks the record incomplete. States that leave a loop through \texttt{break} or \texttt{continue} are joined after it and bypass its \texttt{else}.

Exceptions and other abrupt exits are handled separately. An exception handler starts from the join of every state from which the \texttt{try} body may raise, including states inside nested blocks. A \texttt{finally} block that contains the sink also sees the states at returns and exceptions. Calls that never return, such as \texttt{flask.abort} and \texttt{sys.exit}, end a path when their name is bound by an import and by nothing else. Unmodelled library functions propagate their inputs, as Semgrep does by default, whereas functions defined in the analysed module are treated as unknown because their bodies are not analysed.

\paragraph{Guards.}
An \texttt{if} statement with one branch that always exits makes its condition a \emph{dominating guard} for the statements after it, and enclosing conditions are recorded with the polarity required to reach the sink.

\paragraph{The record.}
The \emph{EvidenceRecord} lists every statement with a stable ID and every definition with its value, its flags and its dependencies, which are the reaching definitions of the variables it reads. It also lists branch feasibility, the dominating guards and a few summary facts, which are the abstract value at the sink, whether the analysis is complete, and the tainted definitions that were pruned as infeasible.

\paragraph{Completeness.}
The record is marked incomplete whenever the analysis meets a construct it does not model, such as a loop that does not converge, \texttt{global}, \texttt{nonlocal}, \texttt{exec} or \texttt{getattr}, comprehensions, \texttt{break} through \texttt{finally}, exception-suppressing context managers, calls to nested functions, or a local container that acquires a second name by assignment, by storage in another container or attribute, or by being passed to an unmodelled call. D and EC never accept a suppression on an incomplete record, whereas E is told that the record is incomplete and decides for itself.

\paragraph{Assumptions.}
D's suppressions rest on four modelling assumptions, which are that only declared sources produce attacker data, that library callees neither read request data themselves nor keep references to their arguments beyond what is modelled, that the analysis is intraprocedural, and that symlinks are out of scope. Stating these assumptions does not make the implementation correct, since D is a bounded implementation whose soundness is tested and not proven, and Section~\ref{sec:correction} reports counterexamples from two reviews that the assumptions did not exclude.

\paragraph{Guard coverage.}
Guard coverage is decided on the dependency structure without comparing variable names. A guard \emph{constrains the sink value} if the definitions it reads lie in the sink's dependency slice, and it \emph{covers every attacker flow} if no taint origin, by which we mean a definition that reads a source directly, can be reached backwards from the sink without crossing those guarded definitions. This distinguishes a check on \texttt{candidate} followed by \texttt{open(name)} from \texttt{open(candidate)}, and it distinguishes a guard in one branch from a guard that dominates both.

\subsection{The four arms after the baseline}
\paragraph{D: closed-set recognizers.}
D suppresses an alert only if the record is complete and the sink is unreachable, the sink value is constant or trusted on every feasible path because of an overwrite or an infeasible branch, or the sink value matches a \emph{recognized containment pattern}. The pattern requires that the sink value is a single definition normalized by an imported \texttt{realpath} or \texttt{abspath}, or by \texttt{resolve()} on a \texttt{pathlib} path, and that a guard dominating the sink tests that same definition with \texttt{v.startswith(root + os.sep)}, with \texttt{commonpath([root, v]) == root}, whose right-hand side must be the root, or with \texttt{v.is\_relative\_to(root)}. The \texttt{root} itself must be built only from constants, module constants or untainted locals whose definitions reach both the guard and the sink. D deliberately leaves string-prefix checks without a separator, containment on an unnormalized path and block-lists such as \texttt{'../' in name} unrecognized. The code also has a route for documented safe APIs, but since no API contract was implemented, that route never fired in any run.

\paragraph{L: ordinary triage.}
The model receives the threat model, the warning with its sink API, argument and line, and the line-numbered source of the enclosing function. It returns JSON containing a decision among \texttt{retain}, \texttt{suppress} and \texttt{unknown}, one of five reason kinds, the supporting lines and a short rationale.

\paragraph{E: evidence triage.}
The model receives the same source and warning, followed by a plain-language digest of the facts and then the full EvidenceRecord. It must assess four obligations, each with a status and cited IDs. \emph{Control} asks whether the value is attacker-controlled, \emph{flow} asks whether it reaches this argument, \emph{confinement} asks whether a check or safe API confines the value that is used, and \emph{coverage} asks whether that argument holds on every path. The model may suppress the alert only if control or flow is refuted, or if confinement and coverage both hold.

\paragraph{EC: the evidence gate.}
EC replays E's responses unchanged and applies a deterministic gate that accepts a suppression only if the reply is valid, every cited ID exists in the record, and the record is complete and was computed for the same file hash. The claim must also match the facts, so that a constant or unreachable claim requires an untainted sink value, a safe-API claim requires a matched contract, and a guard claim requires a cited guard that dominates the sink, constrains the sink value and covers every attacker flow. The gate logs an accepted constant or unreachable claim as \texttt{structural\_check\_passed}, and an accepted guard claim as \texttt{trusted\_contract\_matched} if the guard also matches D's containment recognizer and as \texttt{semantic\_judgment\_remaining} otherwise.

The guard check is a \emph{dependency-consistency} filter, which checks that in the extracted dependency graph every tainted flow to the sink passes through a definition the guard reads, which holds for the program only as far as the extractor is correct, and it leaves open whether the checked value is the consumed value. A transformation applied after the check, such as \texttt{name = target + '/../x'} after a check on \texttt{target}, passes the filter, so whether the predicate and anything applied after it confine the path remains the model's judgment. We keep this category visible because it is where the LLM can add something D cannot and also where it can be wrong. The boundary between D and EC was fixed before the comparative test runs, and since D has no recognizer that the gate lacks, EC can differ from D only where the model asserts confinement by a non-standard guard or where it misses a suppression that D would make.

\subsection{Engineering for a fair comparison}
L and E see the same function source under the same token budget of 12k input and 2k output tokens, and benchmark identifiers and category routes are masked in everything a model sees. Each alert gets one logical call per arm plus a single fixed schema-repair retry, and transport errors are retried with backoff and logged, while answers themselves are never re-sampled. Responses are cached under a key that includes the prompt version and a replicate ID, which lets fresh-generation experiments use new replicate IDs without overwriting the frozen responses. The rule, split, prompts and analyzer were tagged \texttt{protocol-freeze} before any arm was run on test data, and the pipeline refuses test subjects if any frozen file differs from the tag and refuses to overwrite an archived run.

\subsection{Design iterations}
All changes in this subsection were made on development data before the freeze, and the artifact contains the full log. With the first prompt version, p1, E ignored the facts buried in the evidence JSON and misused the reason kinds, so that its false-positive removal on OWASP development cases was 0.29 and that of EC only 0.10. Version p2 puts a fact digest first, defines the reason kinds precisely in the system prompt shared with L and lists every definition, and with it both arms reached 0.86. Development data and regression tests also exposed three soundness bugs. States leaving loops through \texttt{break} were dropped, which made a vulnerable case look constant, \texttt{abort()} was not treated as an exit, and container aliasing went undetected. Finally, the label validator described in Section~\ref{sec:eval} rejected four of our own intended diagnostic labels, which we then fixed.

\subsection{Post-review correctness corrections}
\label{sec:correction}
After the experiments, two independent adversarial reviews of the frozen artifact by GPT Pro constructed programs on which the extractor reported \emph{complete} evidence for a real vulnerability, so that D would suppress a true positive whenever Semgrep alerts at the sink. The first review's witnesses used \texttt{commonpath([R, v]) != v}, which tests containment in the wrong direction, a \texttt{startswith} root taken from the request, a loop \texttt{else} applied after \texttt{break}, a \texttt{return} that skips to a \texttt{finally} containing the sink, and chained or nested container aliasing such as \texttt{a = b = [...]}. While fixing these we found 16 more programs of the same kinds, involving exceptions raised from nested blocks, \texttt{*args} and \texttt{**kwargs} parameters, \texttt{match} captures, mutated module objects, and module or nested helper functions.

The second review found six programs on the corrected extractor. In them keyword arguments to a mutating method were dropped, \texttt{and} and \texttt{or} returned a boolean and evaluated operands that Python skips, a repeated dictionary key kept its first value, and a shadowed \texttt{abspath} or a custom \texttt{resolve()} method was taken as normalization. Fixing these exposed six further holes of the same kinds, among them a shadowed \texttt{abort} that does not exit and a conditional expression whose two branches both took effect. All 34 unsafe programs are now regression tests, alongside 10 safe programs that must stay suppressed, and each program from the second round is also executed to confirm that it really leaves the root.

The corrections are tagged \texttt{review-correction-1} and \texttt{review-correction-2}, and neither changes any of the 220 held-out alert slots, which hold 218 evidence records because one unsupported diagnostic alert has no record in either model's run. The E prompts, the archived E responses and all D, E and EC decisions are therefore unchanged. Offline replays at the second tag run Semgrep and the corrected extractor again, replay the stored model responses and reproduce every held-out decision and score. On the real-world snapshots the first correction changed 16 records, although D still keeps all of them and re-querying the 16 changed E prompts changed no decision, so the frozen results below stand. D remains a bounded implementation whose soundness these programs test without proving it, and the gate's restriction to dependency consistency is unchanged and documented by a test.
