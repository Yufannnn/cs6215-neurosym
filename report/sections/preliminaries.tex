\section{Preliminaries}
\label{sec:prelim}

\paragraph{Analysis problem.}
A Python web handler is vulnerable to path traversal if attacker-controlled data can make a filesystem operation, such as opening, reading, writing, deleting, listing or probing a file, act on a path outside the directory that the application intends to expose. The attacker may use \texttt{..} components, absolute paths that make \texttt{os.path.join} discard its prefix, encodings that are decoded after a check, or prefix confusion, in which \texttt{/srv/files2} passes a string check for \texttt{/srv/files}. We assume POSIX path semantics and leave symlink races, time-of-check/time-of-use attacks and Windows paths out of scope.

\paragraph{Threat model and policy.}
The attacker controls Flask request data, which covers arguments, form fields, headers, cookies, the raw query string and the request path. Route variables passed to a handler as parameters are not declared sources, and module-level constants that no function mutates are trusted. The policy lists the sources, the sinks, which are file operations restricted to their path argument, and one sanitizer, \texttt{secure\_filename}. It also records the documented behaviour of three benchmark helper APIs, for example a request wrapper whose \texttt{get\_safe\_value} returns a constant. The policy is written down three times in mirrored forms, as the Semgrep rule, as the extractor's tables and as the system prompt shared by both LLM arms, so that no arm gets knowledge the others lack.

\paragraph{Baseline: Semgrep taint mode.}
Semgrep~\cite{semgrep} matches code against patterns written in the target language. In taint mode a rule declares \emph{sources}, \emph{sinks}, \emph{sanitizers} and \emph{propagators}, and the engine reports every data-flow path from a source to a sink that does not pass through a sanitizer. Taint flows through assignments and, by default, through function calls, so that a call with a tainted argument yields a tainted result, and propagators add side-effect flows such as \texttt{lst.append(x)} tainting \texttt{lst}. The Community Edition analyzes each function separately, since following flows across functions and files is a feature of the commercial engine, and we confirmed this behaviour on our own fixtures. Semgrep performs constant propagation, although its taint analysis is not path-sensitive and does not interpret guard predicates. With our frozen custom CWE-22 rule on Semgrep CE 1.182.1, which together form the baseline \textbf{S}, it reported flows that pass only through a branch or conditional expression whose condition folds to a constant, such as \texttt{bar = 'safe' if 7*18 + num > 200 else param} with \texttt{num = 106}.

The only community Python CWE-22 rule for Flask in the Semgrep registry is pattern-based and matches only \texttt{open()}, whereas our subjects mostly use \texttt{pathlib} operators, \texttt{codecs.open} and existence checks. We therefore wrote our own taint rule from the policy, developed it only on development data and then froze it. In the pinned version the Python engine does not propagate taint through string slices such as \texttt{s[a:b]}, and because propagators, rule options and taint labels all failed to fix this during development, we kept it as a documented engine limitation. A second loss, in which a value is stored into a dictionary by subscript assignment and read back by key, surfaced only in the failure analysis of the test split after the protocol was frozen, so it was left unaddressed.
